# 课程骨架与脚本设计

这份文档只讲“一讲怎么组织”，不绑定具体学科。计算机专属的映射见 `domains/cs.md`，公式和图标画面见 `visual-grammar.md`。

## 1. 先定义“学会”

在写脚本前，用一句话写清楚学完这一讲用户应该能做到什么。必须是**可观察的动作**：

- 能不看笔记复述主流程；
- 能解释三个“为什么”；
- 能在一个具体例子里算出/判断出结果；
- 能识别一个常见误区；
- 能把方法迁移到一个新例子。

“理解复利”不是目标，无法验收。把目标写成检查题，再倒推脚本。

## 2. 七个必选槽位

任何知识点都应该能回答这七个问题。顺序不要乱；每个槽位只回答一个问题。

| # | 槽位 | 回答的问题 | 旁白目标 | 画面建议 | 时长 |
| --- | --- | --- | --- | --- | --- |
| 01 | `hook` | 不知道它会怎样？ | 一个真实问题、反直觉结果或错误做法 | 前后对比、结果数字、错误示范 | 30–60s |
| 02 | `define` | 它到底是什么？ | 一句话定义 + 一个关键区分 | 定义卡 + 关键词高亮 | 30–60s |
| 03 | `how` | 它为什么/怎么成立？ | 因果链或步骤，必要时拆成 `how1/how2` | 步骤、层次、流程、公式推导 | 60–150s |
| 04 | `example` | 具体跑一遍是什么样？ | 一组具体数字/案例，从头走到尾 | 计数器、演算、时间线、对照 | 60–120s |
| 05 | `boundary` | 什么时候不成立、容易错？ | 边界条件、反例、常见误区 | 正确/错误两栏、临界值 | 45–90s |
| 06 | `apply` | 怎么用、怎么选？ | 使用场景、决策标准、成本 | 决策树、清单、对照表 | 45–90s |
| 07 | `recap` | 带走什么？ | 3–5 句话 + 一个检查动作 | 关键词 chips + 检查卡 | 30–50s |

`how` 可以拆成多段，但每段仍只回答一个子问题。`example` 也可以拆成“简单例子 + 变式”，但不要在一段里塞两个例子。

## 3. 可选模块

按知识点类型选 0–9 个，不要为了凑时长全加。

| 模块 | 什么时候加 | 回答的问题 |
| --- | --- | --- |
| `context` | 需要前置知识或历史背景 | 学它之前要先知道什么？ |
| `compare` | 容易和相邻概念混淆 | 它和另一个东西差在哪？ |
| `derive` | 理科、算法、经济类需要推导 | 这个结论怎么来的？ |
| `misconception` | 有广泛流传的错误理解 | 为什么直觉是错的？ |
| `practice` | 需要手把手做一道题 | 遇到具体问题怎么下手？ |
| `extension` | 有重要变体或进阶用法 | 再往前走一步是什么？ |
| `interview` | 考试/面试场景 | 高频追问怎么答？ |
| `history` | 人文、科学史、事件类 | 它怎么演变到今天？ |
| `demo` | 操作技能、工具、实验 | 实际动作长什么样？ |
| `pronunciation` | 语言学习 | 怎么读、怎么区分？ |

## 4. 时长分档

不要先定“15 分钟”，再往里灌内容。先判断这个知识点需要几个槽位，再得到时长。

| 目标时长 | 段数 | 构成 | 适用 |
| --- | --- | --- | --- |
| 4–6 分钟 | 7–8 | 七个必选；`how` 不拆 | 单个概念、单个操作、单个语言点 |
| 7–10 分钟 | 8–11 | 必选 + 1–3 可选 | 有机制 + 一个例子 + 一个对比 |
| 11–15 分钟 | 11–14 | 必选 + 3–6 可选 | 有前置知识、多个例子、需要练习 |
| 16–20 分钟 | 14–18 | 必选 + 6–9 可选 | 接近一门小课，只在确实需要时使用 |

如果目标时长和内容量冲突，**优先改时长，不要稀释内容**。每段低于 30 秒通常说明拆分过细；每段高于 2 分钟通常说明该拆。

## 5. 从旧版 15 段映射

旧版的计算机/面试骨架可以完整落到新槽位里，不会丢内容：

| 旧段 | 新位置 |
| --- | --- |
| `hook` / `problem` | `hook` |
| `concept` | `define` |
| `structure` / `mechanism` / `mechanism2` | `how`（可拆多段） |
| `example` | `example` |
| `edge` / `contract` | `boundary` |
| `use` | `apply` |
| `contrast` | `compare`（可选） |
| `thread` / `perf` | `extension`（可选） |
| `interview` | `interview`（可选） |
| `recap` | `recap` |

## 6. 跨领域示例

### 例 A：复利（金融/数学）

| 槽位 | 内容 |
| --- | --- |
| `hook` | 10 万，年化 7%，30 年后是多少？答案不是 31 万，是 76 万。 |
| `define` | 复利：利息也参与生息。公式 `A = P(1+r)^n`。 |
| `how` | 第一年利息计入本金，第二年按更大的本金计息；指数增长来自“利滚利”。 |
| `example` | 逐年算 10/20/30 年的余额，指出前期慢、后期快。 |
| `boundary` | 收益率波动、通胀、税费会改变结果；复利不是承诺。 |
| `apply` | 看长期、看费率、看时间；短期看不出差异。 |
| `recap` | 本金、利率、时间、再投资；用 72 法则快速估算翻倍年数。 |

### 例 B：光合作用（生物）

| 槽位 | 内容 |
| --- | --- |
| `hook` | 一棵树几百公斤，物质从哪来？不是从土里。 |
| `define` | 光合作用：光能 → 化学能，把 CO₂ 和 H₂O 变成有机物和 O₂。 |
| `how` | 光反应 + 暗反应；能量和物质的流向。 |
| `example` | 追踪一个碳原子从 CO₂ 到葡萄糖的路径。 |
| `boundary` | 光饱和、温度、CO₂ 浓度限制；夜间只有呼吸作用。 |
| `apply` | 农业增产、温室控制、碳循环。 |
| `recap` | 场所、原料、产物、能量转换、限制因素。 |

### 例 C：英语 /θ/ 和 /ð/（语言）

| 槽位 | 内容 |
| --- | --- |
| `hook` | “think” 和 “sink” 听起来像，但意思完全不同。 |
| `define` | 两者都是舌尖齿间音，区别在声带是否振动。 |
| `how` | 舌位、气流、声带；/θ/ 清音，/ð/ 浊音。 |
| `example` | think/this、three/there、mouth/mother 对比。 |
| `boundary` | 汉语母语者常见替代：用 s/z 或 t/d；词尾容易丢。 |
| `apply` | 最小对立对练习、录音对比、句子跟读。 |
| `recap` | 舌位、气流、声带；用最小对立对自测。 |

## 7. 从旁白到分镜

不要先画图再配旁白。顺序是：

1. **写旁白**：按槽位写，每句一个意思。
2. **标节拍**：在每句旁白后面写“这句话画面要发生什么”。
3. **数句子**：给每段编号 0..n-1，场景渲染器就用这个编号调 `cue(seg, i)`。
4. **再写 HTML**：先搭静态布局，确认不重叠，再加 `renderAt(t)`。

示例（复利 `example` 段）：

| 句子 | 旁白 | 画面节拍 | cue |
| --- | --- | --- | --- |
| 0 | 假设本金十万，年化百分之七。 | 两个数字出现 | `c(0)` |
| 1 | 十年后是十九点七万。 | 10 年结果出现 | `c(1)` |
| 2 | 二十年后是三十八点七万。 | 20 年结果出现 | `c(2)` |
| 3 | 三十年后是七十六点一万。 | 30 年结果出现并高亮 | `c(3)` |

**一张表就是场景的施工图。** 没有这张表就写 `renderAt`，一定会靠猜。

## 8. 脚本写法

### 8.1 开头 30 秒

不要自我介绍，不要“今天我们来学习”。直接给冲突：

> 十万块，年化百分之七，三十年后不是三十一万，是七十六万。

然后立刻给本讲路线：

> 这一讲只回答三件事：复利怎么算，为什么后期增长快，什么情况下它会失效。

### 8.2 中段

- 每个术语第一次出现时，先给直觉，再给名字。
- 每个机制至少配一个具体数字或案例。
- 每讲完一个分支，用一句话收束：“所以这里的关键不是公式，而是时间。”
- 抽象—例子—对比交替，不要连续三段都是抽象描述。

### 8.3 结尾

- 五句话以内复述核心。
- 明确告诉用户现在该做什么：复述、手写、做检查题、找一个新例子。
- 给下一讲的钩子，但不要展开。

## 9. 检查题设计

### 看前基线（5 题）

只暴露盲区，不评分。题目覆盖本讲的五个核心概念，允许“不知道”。

### 看后检查（3 件事）

1. **复述/手写**：不看笔记说出或画出主流程，标出至少两个分支/边界。
2. **追问**：回答 5–6 个“为什么”，每个先结论后一句原因。
3. **应用题**：给一组新数字/新案例，算出或判断出结果。

### 复习节奏

- 即时：看完立刻做看后检查。
- 24h：只看时间轴 + 重做错题。
- 3d：不看视频，尝试完整复述。
- 7d：做一道变式题，检查迁移。

## 10. 自检问题

写完脚本，逐条问：

- 这一讲如果只能记住一句话，是哪句？它在第几段？
- 有没有哪一段删掉后，后面的内容完全不受影响？有就删。
- 每个抽象概念是否都有一个具体例子？
- 代码知识点是否有一个可运行/语义完整的最小例子，展示怎么用、怎么写、输出是什么？例子是否简单但完整、丰富（完整上下文 + 真实输入输出 + 一个变式或边界）？
- 每个“为什么”是否都有因果，而不是“本来就是这样”？
- 有没有把代码/公式/表格逐行念出来？
- 例子里的数字、单位、下标是否前后自洽？
- 结尾是否给了可执行的检查动作？
