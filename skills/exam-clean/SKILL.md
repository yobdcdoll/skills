# 试卷照片 → 干净可打印 PDF

把一张（或跨页两张）手机拍的练习卷，重建成排版整洁、无手写痕迹、可直接打印重做的 PDF/图片。

## 为什么不能用「图像去手写」硬修

先讲清楚，避免走弯路：**不要试图用阈值/滤波把铅笔字从照片里抠掉**。

实测结论（可作为判断依据）：在常见的手机拍照条件下，**铅笔作答的灰度往往比印刷字更深或相当**（例如铅笔核心灰度 ≈89，印刷正文 ≈99，粗体标题 ≈31）。二者灰度区间重叠，任何全局阈值都会「要么留下铅笔灰影，要么把印刷字一起挖掉」。去手写需要专门的 AI 模型（如 DocDiff / DE-GAN），本类环境通常没有 GPU / torch / onnxruntime，跑不动。

**正确路线是「重建」而不是「修图」：**

```
拍图 → 纠偏 + 分页 → 放大读清印刷内容（OCR/视觉） → 用 HTML/CSS 重排印刷题目 → headless 浏览器渲染 → PDF + 拼页 PNG
```

这样得到的是「按印刷内容重新排版的干净卷」，等价于「搭配了文字识别」，且完全可控、可打印。

> 重要：重排时必须**只保留印刷体内容**，把用户的铅笔答案全部丢掉（空卷让重做）。但如果原卷里有**印刷的**答题线/括号/表格，要保留。

> **【核心·必须遵守】保留原卷的留白。** 试卷上的空白**不是排版浪费，而是留给学生写计算过程/作答的空间**。重排时必须把这些留白**等量还原**，否则学生没法做题：
> - **竖式计算**：每题下方要留出足够高度（能容下一道完整竖式，约 3~4 行），不要挤成一行。
> - **看图列式 / 应用题**：要留「算式：____」「答：____」这样的作答区，且下方再留几行空白。
> - **表格题、填空题、选择题**：题干与下一题之间要有明显空白间隔。
> - 判断依据：**照着原照片看**——原图哪块是空的，重排版对应位置也要是空的。宁可多留、多分一页，也不要把留白压掉。

## 环境与依赖

- 有就用的：`python3` + `numpy` + `opencv-python`(cv2) + `Pillow`(PIL)；ImageMagick `convert`；`/usr/bin/google-chrome`（headless 渲染 PDF/PNG）。
- 中文字体：确认有 CJK 字体（`fc-list :lang=zh`）。Noto Serif/Sans CJK 通常可用；HTML 里优先写 `"Noto Sans CJK SC", "Noto Sans SC", sans-serif`。
- 没有也不要紧：本机可能缺 `tesseract` / `pdftoppm` / `qpdf`。因此**不要依赖 tesseract 做中文 OCR**，改用「放大裁剪 + 视觉模型读图」；**不要依赖 pdftoppm 拆页**，改用 PIL 按空白行切图。

先花 10 秒确认这些，再动手：

```bash
python3 -c "import cv2,numpy,PIL;print('ok')"
which convert google-chrome
fc-list :lang=zh | head -3
```

## 工作流

全程在用户工作区建一个子目录（如 `hw_restore/`），不要污染别的文件。

### 步骤 0 · 找到原图并看清它
- 用户上传的图一般在 `/root/.openclaw/media/inbound/`。先 `identify` 看尺寸；如果是**左右跨页**的一张照片，后面要分左右两页。
- 用视觉读一眼整体版面，粗略列出「几个大题、题号、页眉」。

### 步骤 1 · 纠偏 + 分页
用 `scripts/preprocess.py`：

```bash
python3 scripts/preprocess.py <输入图> --outdir hw_restore --split
```

它会：
1. **纠偏**：投影法 + Hough 双验证取角度（经验值常在 -0.9°~-1.05°，但一律以本图实测为准），rotate 回正。
2. **纸张定位**：二值化找最大纸张四边形 bbox，裁掉桌面背景。
3. **左右分页**：中缝一般在宽度 ~0.5 处（本例 538/1080）。按中缝切成 `L_full.jpg` / `R_full.jpg`。

纠偏是否到位，看回正后文字行是否水平；不放心就用 `--debug` 输出中间图目视。**角度不要靠肉眼估**（人眼容易判成 5°+，实测只有 1° 左右）。

### 步骤 2 · 放大裁剪，逐块读清印刷内容
这是准确性的关键。别指望整页一次看全 —— **按「区域」裁剪放大，逐个读**。

用 ImageMagick 裁 + 放大 + 增强（灰度、normalize、sharpen）：

```bash
# 大块（先定位）：裁一段横扫，2~3x 放大
convert R_full.jpg -crop 842x400+0+1560 +repage -resize 250% -normalize /tmp/blk.jpg
# 小块（逐字核对）：小范围 4~6x 放大 + sharpen
convert R_full.jpg -crop 300x46+320+2072 +repage -resize 500% -normalize -sharpen 0x1 /tmp/zoom.jpg
```

然后对每张裁剪图用**视觉模型（image/read）读内容**，而不是自己猜。要点：
- **区分印刷体与手写体**：印刷体笔画规整、均匀；铅笔手写有轻重、抖动、超出格线。**手写的答案一律不采纳**，只认印刷的题干。
- **数字最容易错**：整体字形相似的数字（如 `24` vs `56`、`40` vs `34`）一定单独放大到 4~6x 再确认；必要时逐位截取。
- **遇到「印刷数字被铅笔压住/覆盖」**：多裁几个位偏（x/y 各挪几次）交叉比对，取笔画最规整的那个解释；若仍无法确定，**在交付时明确标注「此处疑似 X，请确认」**，不要默默写错。
- 语文/数学的图形题（竖式、线段图、开火车、表格、水果符号算式）要**连形状一起描述清楚**，重排时才不会走样。

阅读技巧与常见坑见 `references/reading-guide.md`（含「开火车方向」「图形式子」「线段图」的读法）。

**做完这一步，把整页印刷内容整理成一份结构化清单**（题号 → 题干 → 有无图形/表格/空位），这是重排的输入。

### 步骤 3 · HTML/CSS 重排
以 `references/template.html` 为骨架改。它已经内置：
- `@page { size: A4 }` + `.page` 强制分页（一份卷两页就两个 `.page`）；
- 竖式、开火车车厢、线段图、表格、图形式子、填空括号的现成样式类；
- 空卷样式（`______`、`( )` 留白，不写答案）。

改的时候：
- 字体用 `"Noto Sans CJK SC"` 等 CJK 字体，避免中文变方块。
- 保留原卷的**题型结构、题号、每题的图形排布**，让版式接近原练习册。
- 数学竖式用等宽对齐；单位（本/棵/朵/人/岁）不要丢。
- **还原留白（关键）**：竖式计算每题下方留出整道竖式的高度；应用题给「算式」「答」作答区并再留几行空；各题之间保持原卷的空白间隔。需要时用固定高度的空 `<div>`（如 `.work { min-height: ... }`）或空行占位。
  - **留白要「照抄原卷」，不能凭空加**：原卷没有留白的地方（如「不计算·画○/画□」「填一填」「选一选」「勇攀高峰」这类只需在原卷**既有括号/方框**里作答的题），**不要自己再加空白**。判断一律以原照片为准：原图该处紧凑，重排版就紧凑；原图空着的，才留。**留白不足比多留白更糟，但「无中生有」的留白同样是错的**。
  - **页数应与原卷一致**：原卷几张纸，重排就大致排几张。若重排后比原卷多出页，多半是空白块/间距加多了（不是内容真的装不下），应先收掉多余留白再排版，而不是任其溢出到新的一页。**尽量不要用强制分页**（`page-break-after:always`）把页面撑开——先按连续流排版，让它自然分页，再核对页数。
- 页脚/页眉**不要自己添加**：原卷没有的「副标题、页脚、水印、还原说明」等文字一律不加。**只重建原卷上真实存在的内容**，不要添加任何原图没有的元素。
- **顶部学校/班级/姓名表头只在第一页出现一次**：第 2 页起不要再重复标题与姓名/班级/学号栏（除非原卷每页都印了）。

### 步骤 4 · 渲染 PDF + 拼页长图
用 `scripts/render.sh`：

```bash
bash scripts/render.sh restored.html --outdir hw_restore --name 试卷_还原版 --long
```

它会：
1. `google-chrome --headless --print-to-pdf` 出 A4 PDF，渲染后**用正则数一下页数**（`/Type /Page`），确认页数 == `.page` 数，多出来的空页要调 CSS（收紧边距/字号）解决。
2. `--screenshot` 长截图，再用 PIL 按大面积空白行切成单页 PNG。
3. `--long` 把各页纵向拼接成一张长图（仅供自检/备查；默认不作为交付物，交付见步骤 5）。

> 若 chrome 报 `Failed global descriptor lookup` 之类 stderr，通常无害，只要看到 `... bytes written to file` 就成功。

### 步骤 5 · 交付
- **【用户偏好·默认】优先只发 PDF，不要发图片/照片。** 本用户明确要求：交付成果以 **PDF 文件** 为主，聊天里**不要**再发长图/单页 PNG 等图片。
  - 用 `message` 工具 `action=send`，`attachments` 传 PDF：`{"type":"file","path":"...pdf"}`。**不要把文件路径当文字发**，用户看不到。
  - 只有用户**明确要求**看图片（如「发张长图我看看」）时，才额外发 PNG。
- 渲染产物里的 PNG（单页/长图）仍按需生成以便自检，但**默认不作为交付物发送**。
- 若环境有 `present_files` 工具，再补一次 `present_files`（只放 PDF）。
- 交付时附一句**「我改了/补了哪些」**，并**标注任何存疑的数字/题目**请用户确认。

## 常见坑（血泪版）

1. **纯算法去铅笔 = 死路**。灰度过重叠，别浪费时间调阈值。
2. **别用肉眼估纠偏角**。用投影/Hough 实测。
3. **别整页一次性 OCR**。中文试卷必须分块放大读，否则漏题、错数字。
4. **手写答案不是题干**。题干里若含手写，要剥离并还原成空白。
5. **漏题**：右页/下半页很容易漏。读完一个「大题」后，**再看下一段文字是不是新题号**（如「三、」「四、」），确认没跳过整块内容。
6. **PDF 多出空页**：`.page` 后加 `page-break-after:always`，并给 `h2/.q/table` 等加 `page-break-inside:avoid`；必要时收紧 `@page margin`。
7. **数字矛盾要警觉**：题干数字与用户答案/草稿对不上时（例：题面写「共有 24」，但答案 32+24=56），以**印刷体**为准，并明确告知用户存疑点。
8. **文件别乱丢**：一律放工作区子目录；原图只读，不改写。
9. **留白要照抄原卷，不能凭空加/凭空减**：原卷的空白是「作答区」，必须等量还原（竖式计算、应用题）；但原卷**没有**留白的地方（画○/画□、填一填、选一选等只用既有括号作答的题）**不要自己加空白**。两个方向都错：漏留白让学生没法写，凭空加留白又与原卷不符。
